# 参考方案 · 惊蛰 6.7 —— 完整结构分析（hook 改客户端）

> 这是**别人已经做好的**原神 6.7 安卓改客户端方案（非代理），是「改包路线」的成熟蓝本。
> 本文对它做**逐条目、逐符号**的完整拆解：改了什么文件、怎么加载、RSA 公钥怎么换、流量怎么重定向、怎么签名。
>
> 来源包：`惊蛰6.7.apk`（468,794,110 B，包内时间戳 2026-07-12 ~ 2026-08-30）。本文只记录**方法与数据**，不含官方 APK 本体。

## 0. 结论速览

| 维度 | 惊蛰 6.7 的做法 |
|---|---|
| 加载 hook | 改 `libyuanshen.so` 的 **DT_NEEDED**（第 0 项加 `libclienthook.so`），链接器自动加载，**不碰 dex/manifest** |
| 真正干活的 hook | **`libclienthook.so`**（4.2 MB，内联 And64InlineHook + 字符串 XOR 混淆），自己 hook `ReadToEnd` 换公钥 |
| RSA 替换 | 运行时把客户端读到的 **原版 CN 公钥字符串**（415 字符 XML）**原地覆盖**为**自建服公钥**（同 415 字符） |
| 重定向 | blk 的 `DispatchUrls` + `server_env_config.json`（1604 条）+ `classes3/4.dex`（69 条）→ 全部指向**公网域名** `sdk.yuanshen.org.cn` |
| 服务端 | 公网：`sdk.yuanshen.org.cn` → `106.14.151.240`（阿里云） |
| 签名 | 用 **Android 默认 debug keystore** 重签 |
| 改名 | `resources.arsc` 应用名 → `惊蛰公益原神67` |

**一句话**：惊蛰 = 「DT_NEEDED 注入一个自写 hook 库」+「把所有 SDK 端点域名换成自己的公网域名」+「运行时替换区服签名公钥」。因为服务端在**公网域名**，它**不需要**绕「4214 域名指向校验」（校验要求请求是域名、且很可能要求解析到公网 IP）。

## 2. 加载链（⚠️ 更正上一版的错误）

```
libyuanshen.so
  DT_NEEDED[0] = libclienthook.so      ← 惊蛰注入的第 0 个依赖
        │  链接器加载 libyuanshen.so 时自动把 libclienthook.so 一起加载
        ▼
libclienthook.so  (4.2 MB, NDK r21b, stripped)
        │  内联 And64InlineHook（自带 A64HookFunction），字符串 XOR 混淆
        │  INIT_ARRAY 里起线程等 libyuanshen.so 就绪
        ▼
  hook libyuanshen.so 的 ReadToEnd  →  命中「原版 CN 公钥」时原地改写为自建服公钥
```

**为什么说上一版错了**：
- `libclienthook.so` 的导入表里**没有 `dlopen`**（只有 `dl_iterate_phdr / mprotect / pthread_create / nanosleep / strrchr / strcmp / snprintf / memcpy / memset / __android_log_print`），它**无法**按名字加载别的库。
- 在 `libclienthook.so` 里搜 `libreadtoendhook` / `readtoend`（含 XOR 变体）→ **0 命中**。
- 全部 dex 里搜 `clienthook` / `readtoendhook` → **0 命中**。
⇒ **`libreadtoendhook.so` 没有任何地方引用它**，是作者 07-30 **11:28** 的早期独立实现，被 **15:02** 的 `libclienthook.so` 取代后**忘在包里没删**（死文件）。
真正的 hook 逻辑在 `libclienthook.so` 内（它自带 And64InlineHook，证据：`A64_HOOK`、`failed to allocate trampoline!`、`mprotect failed with errno = %d, p = %p, size = %zu`、`ref_idx must be less than or equal to current_idx!` 等字符串与 libreadtoendhook 同源）。

**DT_NEEDED 证据**（`readelf -d libyuanshen.so`）：

```
 (NEEDED)  Shared library: [libclienthook.so]   ← 注入（其余 libc/libm/libandroid/libdl/liblog/libGLESv2/libz/libEGL 均正常）
 (SONAME)  Library soname: [libyuanshen.so]
 (INIT_ARRAY) 0x15858378   INIT_ARRAYSZ 6472
```

**为什么用 DT_NEEDED**：写进 `libyuanshen.so` 的 `DT_NEEDED` 数组后，Android 链接器加载 `libyuanshen.so` 会自动连带加载 `libclienthook.so`，
**无需改 dex、无需改 Application、无需改 manifest**。

## 3. RSA 公钥替换（完整还原）

### 3.1 目标函数

`libyuanshen.so`（IL2CPP/C#）里的 **`ReadToEnd`**：把某个流/文本读成字符串，**返回的是 IL2CPP 字符串对象**（`Il2CppString*`）。

`libclienthook.so` hook 它，拿到返回值后判断：
- `[obj + 0x10]`（length）== **415**（`0x19f`）
- `[obj + 0x14]`（首字符）== `'<'`（`0x3c`）
- 全串 == **原版 CN 公钥**（`kCnOriginal`）

命中 ⇒ 把对象里的 415 个 UTF-16 字符**原地覆盖**成**自建服公钥**（`kCnReplacement`）。日志：`replaced CN public key, count=%d`。

### 3.2 两把钥匙（都是 2048-bit RSA 的 `<RSAKeyValue>` XML，**正好都是 415 字符**）

> 长度一致是关键：原版公钥字符串是 415 字符，替换公钥也**刻意做成 415 字符**，才能**原地等长覆盖**。

### 3.3 混淆方式（这就是上一版"漏掉"的原因）

作者对字符串做了 **XOR 混淆**，`strings` 直接扫**看不到**：

| 字符串 | 存储 | XOR key |
|---|---|---|
| 原版 CN 公钥 `kCnOriginal` | libclienthook.so `.data` | **0x42** |
| 自建服公钥 `kCnReplacement` | libclienthook.so `.data` | **0x27** |
| `libyuanshen.so`（目标模块名） | libclienthook.so `.data` | **0xd9** |
| `ReadToEnd` | libclienthook.so `.data` | **0x7f** / 0x98 |
| `/REPLACED`、`PUBLIC`、`OCCURRENCES`、`TOTAL` | libclienthook.so `.data` | **0x08** |

> 另外 `libreadtoendhook.so` 里同一把自建服公钥用的是**另一种混淆**：存成 **UTF-16，并切成 16 字节块、打乱顺序**分散在 `.rodata`，
> 运行时用一堆 `ldr q`/`stp q`（NEON）**按指定顺序搬回**字符串对象。所以 ASCII `strings` 也扫不到它。

### 3.4 定位/校验逻辑

- 目标函数用 **prologue 常量** `fe0f1df8 f65701a9 f44f02a9`
  （`str x30,[sp,#-0x30]! ; stp x22,x21,[sp,#0x10] ; stp x20,x19,[sp,#0x20]`）来定位/校验，
  该 12 字节常量硬编码在 `libclienthook.so` `.rodata @0xb08`。
- 失败日志：`ReadToEnd RVA or prologue does not match this libyuanshen.so build`
  （即：**版本不对就放弃**，不会崩）。
- 成功日志：`replaced CN public key, count=%d`；
- 另有 `ReadToEnd hook active; first result length=%d, target CN public key not present`。

### 3.5 为什么这样能过「签名校验」

客户端对 `query_cur_region` 返回的 `sign` 用**自己内存里的 ServerPub** 验签。
把内存里那把公钥换成服务端的公钥后，客户端就会用**服务端的公钥**去验服务端签的名 ⇒ 自然通过。
**不需要**知道米哈游真正的私钥，也**不需要**静态改 dex（无 `string_ids` 排序坑）。

## 4. 重定向（完整）

### 4.1 `assets/20527480.blk`（dispatch 配置）

- Blb 容器（`42 6c 62 03` + `75 00 00 00` + `05 00 00 00` + 31 B 每文件不同 + LZ4 block）。
- 惊蛰版 **1,168 B**（最小），用**带预置字典的 LZ4**（首个 match offset ≈ 4 万 ⇒ 字典 ≥ 40 KB）。
- 字典未知（游戏端从 libyuanshen 的 LZ4 字典来），**当前解不开**；据社区/作者信息：
  `DispatchUrls → http://sdk.yuanshen.org.cn/query_region_list`（**域名**，非 IP），`RSAParam.keyId = 3`。
- 31 字节字段非任何常见哈希/XOR（8 个样本全不匹配），**重打包保留原值**。

### 4.2 `assets/server_env_config.json`（SDK 端点总表，169 KB）

- 结构：**8 套 env** 的数组，每项含 `api_sdk_domain / game_api_domain / data_report_domain / passport_env / url{...大字典...}`。
- 改写结果：**1604 条 URL → `https://sdk.yuanshen.org.cn`**（account/combo/passport/sdk/支付/上报全覆盖）。
- 另有 **2 处** 日志上报写死 IP：`http://106.14.151.240:8092/log/sdk/upload`。
- 残留的 `*-os.hoyoverse.com` 是**国际服(OS)端点**，CN 用不到，未改。

### 4.3 `classes3.dex` / `classes4.dex`（登录/SDK 域名）

- 各把 SDK 域名换成 `https://sdk.yuanshen.org.cn`：classes3 = **28** 条、classes4 = **41** 条（共 69）。
- 残留的 `https://sdk.yuanshen.org.cn/mihoyo/common/...` 里的 "mihoyo" 只是**路径段**，host 已是 yuanshen.org.cn。
- 残留 `minor-api-os / sandbox-sdk-os-static / sdk-common-static …hoyoverse.com` 为国际服端点，未改。
- classes4 还含 `ma-cn-passport`（19 处）等登录端点 —— 说明**登录链路**也走了自建服（靠 §3 的公钥替换 + 域名替换共同完成）。

### 4.4 `classes.dex`

- 含 **combo/MDK SDK**（`com.combosdk.forMDK.PluginImpl` 等）与支付/遥测类；**无任何可重定向的 URL**（0 条 mihoyo 完整 URL）。
- 07-12 被改动过，但**具体改了什么未能确认**（需官方 6.7 原包做二进制 diff）—— 见 §6。

### 4.5 结论

惊蛰把所有 SDK 端点指向**自己的公网域名**，dispatch 也用域名。⇒ 它**没有对抗「4214 域名指向校验」**，
而是「服务端本来就在公网」。这解释了为什么我们的**本地 `127.0.0.1` 改包路线**会触发 4214（IP 指向）。

## 7. 移植到 7.1 的要点（对我们）

1. **加载方式**：给 `libyuanshen.so` 的 `DT_NEEDED` 追加一个自写 `libclienthook.so`（链接器自动加载，免改 dex/manifest）。**别信"用 libreadtoendhook 那种独立库"**——要么直接写一个自包含 hook 库。
2. **RSA 替换**：hook `ReadToEnd`，等返回 415 字符的 `<RSAKeyValue>` 字符串时**原地覆盖**成自建服公钥（**必须等长**）。
   - 7.1 的难点：原版公钥**非明文**（在 MHY0 加密的 `global-metadata.dat` 内 / 运行时构造），且 `ReadToEnd` 的 RVA/特征未知。
   - 变通：hook 的判据可以**放宽**为「length == 415 且首字符 `'<'` 且含 `<RSAKeyValue>`」，不必硬编码原版公钥。
3. **重定向**：blk（域名）+ `server_env_config.json`（或 7.1 对应的 TextAsset）+ dex 域名。
4. **4214**：要么服务端放到**公网域名**（学惊蛰），要么**hook 掉客户端的域名校验**。
5. **签名**：debug keystore 即可（我们已有 `keystore/yspatch.keystore`）。
