# 参考方案 · 惊蛰 6.7 —— 「hook 改客户端」完整流程

> 这是**别人已经做好的**原神 6.7 改客户端方案（非代理），是「改包路线」的成熟蓝本。
> 本仓库把它的**流程与关键材料**收录，作为 7.1 移植的参考。
>
> 来源包：`惊蛰6.7.apk`（468MB，2026-07-12 构建）。本文只记录**方法**，不含官方 APK 本体。

---

## 1. 它和我们「改包路线」的区别

| | 我们（redirect2/3/4） | 惊蛰 6.7 |
|---|---|---|
| 登录公钥替换 | **静态**改 `classes4.dex` 里的公钥字符串 | **运行时** hook，把客户端读到的公钥**动态**换成自建服公钥 |
| 对版本变化 | 公钥/域名一换就要重新找位置 | 只要 `ReadToEnd` 的 RVA 对得上，改一个数字即可 |
| 加载方式 | 改 dex / assets | 改 `libyuanshen.so` 的 **DT_NEEDED**，链接器自动加载 hook 库 |
| 服务端位置 | 本地 `127.0.0.1` | **公网** `sdk.yuanshen.org.cn`（106.14.151.240） |

> 结论：惊蛰这套**更通用、更优雅**（运行时 hook，不碰 dex 的字符串排序），但需要写原生 hook 库。

## 2. 加载链

```
libyuanshen.so  (DT_NEEDED 里追加 libclienthook.so)
      │  链接器启动时自动 dlopen
      ▼
libclienthook.so  (4.2MB，打包/加密的 hook 框架，字符串极少)
      │  构造函数里拉起
      ▼
libreadtoendhook.so  (55KB，And64InlineHook)
      │  等 libyuanshen.so 加载后，hook 其中的 ReadToEnd
      ▼
每次 ReadToEnd 返回「原版 CN 公钥字符串」时 → 原地替换成自建服公钥
```

**为什么用 DT_NEEDED**：把库名写进 `libyuanshen.so` 的 `DT_NEEDED` 数组，Android 链接器加载
`libyuanshen.so` 时会自动把 `libclienthook.so` 一起加载，**无需改 dex / Application 代码**。

## 3. libreadtoendhook.so 细节（反汇编 `libreadtoendhook.asm`）

关键字符串：

```
ReadToEndHook
installed at base=%p RVA=0x%lx target=%p
ReadToEnd RVA or prologue does not match this libyuanshen.so build
replaced CN public key, count=%d
libyuanshen.so
A64_HOOK
```

工作流程：

1. **构造函数起线程轮询**，用 `dl_iterate_phdr` 遍历已加载模块，用 `strrchr`/`strcmp`
   找到 `libyuanshen.so` 的基址。
2. 校验目标函数**前 12 字节 prologue** 是否匹配（防止 hook 错版本）：
   ```
   fe0f1df8  f65701a9  f44f02a9
   str x30,[sp,#-0x30]! ; stp x22,x21,[sp,#0x10] ; stp x20,x19,[sp,#0x20]
   ```
   不匹配就打印 `ReadToEnd RVA or prologue does not match this libyuanshen.so build` 并放弃。
3. 用 **And64InlineHook（`A64HookFunction`）** 在 **`ReadToEnd`，RVA = `0x13d0d8ac`（6.7 专用）**
   处下 hook。
4. hook 内：调用原函数拿到返回的**字符串对象**，若满足
   `[obj+0x10] == 415 && [obj+0x14] == 0x3c('<')`（长度 415、首字符 `<`）
   且内容 == 硬编码的原版 CN 公钥，则**原地改写为自建服公钥**，计数 `replaced CN public key, count=%d`。

硬编码的**原版 CN 公钥**（`<RSAKeyValue>` XML 形式，415 字符）：

```
<RSAKeyValue><Modulus>lCwdYrveozYYcKOSz4cjBfORvd6POZSxsM9JybWvTb9rr1qGhulgoNcMB0sUA4XnfNlt/aaT+JKSTEgynyX8of74Nmu70MRO2Nemi0YnI56gK2f0tIdmpFKnojgDTlLslQnKBzcK/elbcX2XE3FMK/hA2rkJBIMkIsXJ23nfWy/6KFB/nhXft+wzDahYmzaoLKsgq4xQInB6n0dUSkFNSMV+98CRjh+Y7pXlyEglDXxj+IhBVsl8s41c9vmgLHWS7feMufbeqko83fLv2GlI/aU0pvmYr9Lyf4kgPMp5aTqeyCm/ztb3bp5QoW7S2hlGP6gtxGr4s/lMpZN5YgTZbQ==</Modulus><Exponent>AQAB</Exponent></RSAKeyValue>
```

> ⚠️ **对 7.1 不通用**：`ReadToEnd` 的 RVA 和原版 CN 公钥都随版本变化。
> 7.1 的 `libyuanshen.so` / `global-metadata.dat` 里**搜不到** `lCwdYrve` / `RSAKeyValue` / `<Modulus>`
> ⇒ 7.1 公钥已轮换且**非明文**（运行时构造），此 hook 不能直接套用。

## 4. 它的资源/端点配置

**blk**（`assets/20527480.blk`，1168B，字典 LZ4）：

```jsonc
"DispatchUrls": [ "http://sdk.yuanshen.org.cn/query_region_list" ],   // 域名，非 IP
"RSAParam": { "keyId": 3 }
```

**`assets/server_env_config.json`**：所有 SDK 端点 → `https://sdk.yuanshen.org.cn`；
另有上报 `http://106.14.151.240:8092/log/sdk/upload`。

⇒ 参考包的**服务端在公网**（域名 `sdk.yuanshen.org.cn` → 阿里云 `106.14.151.240`）。
很可能它**并没有绕「域名指向校验」，只是服务端本来就在公网**。

## 5. 复现流程（把它移植到某版本）

1. **准备服务端**：一个**公网可访问**的域名（避免 4214 域名校验），部署 Grasscutter/AstaPS，
   配置 `accessAddress` 为该域名。
2. **改 blk**：`DispatchUrls` → `http://<你的域名>/query_region_list`（保留域名形态）。
3. **改端点表**：`assets/server_env_config.json`（或对应 TextAsset）里所有
   `*.mihoyo.com` / `*.hoyoverse.com` → 你的域名。
4. **写 hook 库**（核心）：
   - 用 **And64InlineHook / Dobby / xhook** 之类 inline hook 框架；
   - 找到目标函数（本例 `ReadToEnd`）在**目标版本** `libyuanshen.so` 里的 **RVA 与 prologue**；
   - 在 hook 里把返回的公钥字符串替换成你服务端的公钥；
   - 用 `dl_iterate_phdr` + prologue 校验，确保只 hook 正确版本。
5. **加载 hook 库**：把库名追加进 `libyuanshen.so` 的 **DT_NEEDED**（或用 `libclienthook.so` 那种
   一级加载器拉起）。
6. **签名安装**：重签 APK，安装。

### 找 RVA / prologue 的方法（免 root）

- 用 **Il2CppDumper** 导出 `libyuanshen.so` + `global-metadata.dat` 的符号表，搜函数名。
- 或在**已 root 设备**上用 Frida：`Module.findExportByName` / 扫描特征。
- 或对 `libyuanshen.so` 反汇编，按字符串交叉引用定位。
- 拿到 RVA 后，把**函数前 12 字节**作为 prologue 写进 hook 库做校验。

## 7. 关键结论

1. **hook 路线**是「一劳永逸」的改客户端方式：不用改 dex（无字符串排序坑）、
   不用改 assets（除域名），版本升级只需更新 RVA 与公钥。
2. **公网服务端**可规避「4214 域名指向校验」——因为校验要求的是「域名」而非「IP」，
   且（可能）要求解析到公网 IP。本地 `127.0.0.1` 需另想办法（见 README §10.2/§10.3）。
3. 移植到 7.1 的难点：**7.1 的公钥非明文、`ReadToEnd` RVA 未知**，需要逆向
   `libyuanshen.so`（IL2CPP）或解密 `global-metadata.dat`（MHY0）。
